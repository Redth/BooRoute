# Demo inline reviews

This is a presentation aid, **not a merge gate or a full code/security review**.
After this workflow is merged, every opened, reopened, updated, or retargeted PR
(including drafts and forks) receives up to two inline demo comments. The workflow
can also be dispatched with an open `pr_number`.

The actual gh-aw source is `.github/workflows/demo-review.md`; its `.lock.yml`
is generated by gh-aw v0.86.2. The shared engine definition is
`.github/workflows/shared/booroute-gpt.md`. This behavior-defined engine makes one
request to OpenAI using **`gpt-4.1-mini` only**, with no retries,
agent tools, additional evaluators, or alternative models. It samples the first
two changed files and at most 4,000 patch characters per file.

## Setup

Enable GitHub Actions. To enable actual GPT feedback, create the repository
Actions secret **`OPENAI_API_KEY`** with an OpenAI project key authorized for
`gpt-4.1-mini` and Chat Completions, with available quota. Do not add a personal
GitHub token: the automatic `GITHUB_TOKEN` supplies repository access. Allow the
trusted publisher job `pull-requests: write` so it can leave review comments.
Without `OPENAI_API_KEY`, the workflow immediately produces explicitly labeled
**deterministic fallback questions**, not claims that GPT ran successfully.
Model access errors, rate limits, timeouts, and unusable output use the same
honest fallback. GitHub Models is deliberately not used: that service was retired
on July 30, 2026.

The publisher always submits `COMMENT`, never `APPROVE` or `REQUEST_CHANGES`.
It supports additions, `LEFT`-side deletions, and file-level comments when GitHub
provides no text hunk (for example binary or rename-only changes). An empty PR has
no possible inline anchor; that condition is logged rather than inventing one.
GitHub API failures, runner/setup failures, cancellations, or disabled Actions
can prevent comments entirely.

## Timing and safety

The model HTTP request is independently aborted after **30 seconds**, including
reading its response. The agent execution step is capped at **one minute**. The
publisher process has a 55-second timeout and a five-second forced-kill grace
period, for a combined two-minute review-work budget. Each script has a 50-second
network deadline. This is not a two-minute end-to-end wall-clock guarantee:
gh-aw is multi-job, and GitHub queueing, runner provisioning, job transitions,
action downloads, and cancellation handling can add latency. It does not run
the usual long, tool-driven review loop.

PR contents are untrusted data, never shell source or executable instructions.
Only the trusted base-repository revision is checked out, never the PR head,
with persisted credentials disabled. The model prompt contains bounded diff samples, never a credential or
write token, and the model cannot call tools. The read-only engine emits a
validated safe-output request; a separate trusted publisher checks the current
PR head **and base** before each write. Model output cannot choose the repository,
PR, revision, or comment path.
`strict: false`, the disabled agent sandbox, and the disabled extra AI
threat-detection pass are deliberate, narrow demo exceptions: this fixed engine
only performs trusted HTTP/JSON processing, never agent-generated code. Do not
reuse that exception for a general-purpose agent.

Hidden markers scope comments to this workflow, revision, and sampled location.
Reruns do not add duplicate comments. A successful GPT rerun can upgrade an
existing fallback in place; already-posted GPT feedback is retained. A new revision
gets fresh anchors, while old comments remain in GitHub's review history.

Recompile after editing the source or engine script:

```sh
gh aw compile demo-review --validate --actionlint --no-check-update
```

Commit the sources and compiler-generated lock/pin files, including
`.github/aw/actions-lock.json`. Do not hand-edit generated files.
